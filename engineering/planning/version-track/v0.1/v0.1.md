# v0.1 — File store

*Last updated: 2026-11-09*

**Status:** 🚧 In Progress · **Type:** Feature · **Started:** 2026-10-26 · **Completed:** —

### Iteration 1 — File types

- [x] Ability to recognize a file's type from its name and its bytes
- [x] Ability to reject a file whose bytes contradict its claimed type
- [x] Ability to sanitize a file name for storage and download
- [x] Ability to show an icon for any file extension

### Iteration 2 — Storage

- [x] Ability to scope every file to a tenant
- [x] Ability to upload a file through the API under an app policy
- [x] Ability to store each file's bytes once per tenant
- [x] Ability to retry an upload without storing a duplicate
- [x] Ability to read, list and rename a file
- [x] Ability to delete a file, restore it and purge it after retention

### Iteration 3 — References

- [x] Ability to attach a file to a record and detach it
- [x] Ability to sweep files no record references
- [x] Ability to expire files after a set number of days

### Iteration 4 — Delivery

- [x] Ability to hand out a short-lived signed URL for a private file
- [x] Ability to serve a public file at an immutable cached URL
- [x] Ability to stream a byte range of a file
- [x] Ability to serve user content that never runs as active content

### Iteration 5 — Service

- [x] Ability to call every broker over `/api/files/v1`
- [x] Ability to call the service with a client-credentials token
- [x] Ability to call the service with a tenant API key
- [x] Ability to switch between Module and Client with no code change
- [x] Ability to see an audit row for each upload, delete and download

### Iteration 6 — Sample polish

- [x] Remove the Greetings sample from the packages, service and tests
- [x] Remove the Greeting widget from `fe-files` and `apps/web`

### Iteration 7 — Review fixes

- [x] Ability to load any file type's icon from the service's web root, from any origin

### Iteration 8 — Identity

- [x] Re-pin the be sdk to `10.0.103-beta` or later; take Identity `Auth` and `Testing` at `10.0.29-beta` (files-integration #37)
- [x] Ability to read every caller through one principal: person, service or key (files-integration #8, #9)
- [x] Ability to trust each tenant's issuer and audience on one host (files-integration #15, #21, #35)
- [x] Ability to authenticate a tenant's API key through Identity's key scheme (files-integration #16)
- [x] Ability to require a person's `files:` permission beside the app's scope (files-integration #23, #36)
- [x] Ability to call the service for a person through token exchange (files-integration #13)
- [x] Ability for the client to get its own token: client credentials or exchange (files-integration #11, #13)
- [x] Ability to refuse a revoked person's token before it expires (files-integration #19)
- [x] Ability to tell people with one `sub` from two issuers apart (files-integration #22)
- [x] Drop the `files.delegate` scope; scopes are read, write, share, admin and tenants (files-integration #10, #12)

### Iteration 9 — Imports

- [x] Ability to open an import for a tenant with the operator key (files-integration #38)
- [x] Ability to push a legacy file into an import with its key, hash and reference
- [x] Ability to read an import's progress and its id map
- [x] Ability to move files from a folder, a SQLite column or a PostgreSQL column with the mover

### Iteration 10 — Variants

- [x] Ability to make WebP variants at an app's widths on upload
- [x] Ability to serve a variant at its own public URL or through a signed one

### Iteration 11 — Verification

- [x] Open a signed URL after it expires → refused.
