# v0.1 — File store

*Last updated: 2026-11-08*

**Status:** 🚧 In Progress · **Type:** Feature · **Started:** 2026-10-26 · **Completed:** —

### Iteration 1 — File types

- [x] Ability to recognize a file's type from its name and its bytes
- [x] Ability to reject a file whose bytes contradict its claimed type
- [x] Ability to sanitize a file name for storage and download
- [x] Ability to show an icon for any file extension

### Iteration 2 — Storage

- [x] Ability to scope every file to a tenant
- [x] Ability to upload a file through the API under an app policy
- [x] Ability to store each file's bytes once per tenant
- [x] Ability to retry an upload without storing a duplicate
- [x] Ability to read, list and rename a file
- [x] Ability to delete a file, restore it and purge it after retention

### Iteration 3 — References

- [x] Ability to attach a file to a record and detach it
- [x] Ability to sweep files no record references
- [x] Ability to expire files after a set number of days

### Iteration 4 — Delivery

- [x] Ability to hand out a short-lived signed URL for a private file
- [x] Ability to serve a public file at an immutable cached URL
- [x] Ability to stream a byte range of a file
- [x] Ability to serve user content that never runs as active content

### Iteration 5 — Service

- [x] Ability to call every broker over `/api/files/v1`
- [x] Ability to call the service with a client-credentials token
- [x] Ability to call the service with a tenant API key
- [x] Ability to switch between Module and Client with no code change
- [x] Ability to see an audit row for each upload, delete and download

### Iteration 6 — Sample polish

- [x] Remove the Greetings sample from the packages, service and tests
- [x] Remove the Greeting widget from `fe-files` and `apps/web`

### Iteration 7 — Review fixes

- [x] Ability to load any file type's icon from the service's web root, from any origin

### Iteration 8 — Identity

- [ ] Re-pin the be sdk to `10.0.103-beta` or later; take Identity `Auth` and `Testing` at `10.0.29-beta` (files-integration #37)
- [ ] Ability to read every caller through one principal: person, service or key (files-integration #8, #9)
- [ ] Ability to trust each tenant's issuer and audience on one host (files-integration #15, #21, #35)
- [ ] Ability to authenticate a tenant's API key through Identity's key scheme (files-integration #16)
- [ ] Ability to require a person's `files:` permission beside the app's scope (files-integration #23, #36)
- [ ] Ability to call the service for a person through token exchange (files-integration #13)
- [ ] Ability for the client to get its own token: client credentials or exchange (files-integration #11, #13)
- [ ] Ability to refuse a revoked person's token before it expires (files-integration #19)
- [ ] Ability to tell people with one `sub` from two issuers apart (files-integration #22)
- [ ] Drop the `files.delegate` scope; scopes are read, write, share, admin and tenants (files-integration #10, #12)

### Iteration 9 — Verification

- [ ] Run `dotnet test` → every tier green, Module and Client conform.
- [ ] Upload a JPEG renamed to `.png` → rejected as a content mismatch.
- [ ] Upload one file twice in a tenant → one stored blob, two file rows.
- [ ] Open a signed URL after it expires → refused.
- [ ] Detach a file's last reference, sweep → purged after retention.
- [ ] Request a range of a public video → `206` with the requested bytes.
- [ ] Open the icon page → every registry extension shows its icon.
- [ ] Load `/icons/pdf.svg` in an `<img>` on another origin → the PDF icon shows.
- [ ] Call with a token from an issuer the host doesn't trust → `401`.
- [ ] Call with a tenant's token at another tenant's audience → `401`.
- [ ] Call as a person holding `files.read` but no `files:read` → `403`.
- [ ] Signal a person's ended session, then call with its token → `401`.
- [ ] Upload as one `sub` from two issuers → two owners.
- [ ] Call through `Files.Client` as a service and for a person → both pass against a fake issuer.
